## Python 3.11 이상 필요

v1.5에서는 `requires-python`을 `>=3.11`로 변경합니다. 지원 범위는 Python
3.11~3.14이며, Python 3.15 프리릴리스도 실패를 허용하는 CI에서 계속
검증합니다. [PEP 790](https://peps.python.org/pep-0790/)에 예정된 2026년 10월
1일 정식 출시 이후 전체 테스트를 통과하면 필수 지원 매트릭스로 승격하는 것을
기준으로 합니다.

Python 3.8과 3.9는 이미 Python 자체의 지원이 종료됐습니다. Python 3.10은
현재 지원 종료 상태가 아니며 **2026년 10월까지 보안 지원**을 받습니다. 다만
v1.5의 새 유지보수 계열을 시작하는 시점에는 남은 공식 지원 기간이 매우 짧습니다.
3.10을 v1.5에 포함하면 출시 직후 계열 중간에서 최소 버전을 다시 올리거나, 계열
수명 대부분에 걸쳐 지원 종료 인터프리터를 유지해야 합니다.

따라서 “출시일 당일 지원되는가”만 보지 않고, 같은 마이너 계열에서 일관된 지원
정책을 유지할 수 있는지를 기준으로 3.11을 선택했습니다. Python 3.11은
**2027년 10월까지 보안 지원**을 받아 1.5 계열에 의미 있는 유지보수 기간을
확보합니다. 각 버전의 현재 상태와 종료 일정은
[Python 개발자 가이드의 버전 표](https://devguide.python.org/versions/)에서 확인할
수 있습니다.

Python 3.8~3.10 환경에서는 v1.4.x가 마지막 설치 가능 계열입니다.

```bash
python -m pip install "hangulpy<1.5"
```

## 제거 예정 호환 API

v1.4는 Python 명명 규칙에 맞춘 새 이름을 도입하면서 기존 호출을 한 릴리즈 동안
호환합니다. 아래 세 이름은 사용 시 `DeprecationWarning`을 발생시키며 **v1.5에서
제거될 예정**입니다.

| 제거 예정 이름 | 대체 이름 |
| --- | --- |
| `chosungIncludes` | `chosung_includes` |
| `notallowempty` | `not_allow_empty` |
| `allowDoubleConsonant` | `allow_double_consonant` |

## 검색 옵션

`hangul_contains`, `hangul_search`, `hangul_search_all`과 `HangulSearcher` 메서드의
호출을 다음처럼 바꿉니다.

```python
from hangulpy import hangul_contains

hangul_contains("사과", "", not_allow_empty=True)
```

## 키보드 변환 옵션

`enko`, `autofix`, `convert_qwerty_to_hangul`에서는 snake_case 옵션을 사용합니다.

```python
from hangulpy import enko

enko("rrk", allow_double_consonant=True)
```

새 이름과 제거 예정 이름을 한 호출에서 함께 넘기면 `TypeError`가 발생합니다.

## 경고 표시와 필터링

호환 API는 Python 표준 `warnings.warn`과 `DeprecationWarning`의 하위 클래스인
`HangulpyDeprecationWarning`을 사용합니다. 따라서 일반적인 Python 경고 필터,
`-W` 옵션, `PYTHONWARNINGS` 환경 변수로 표시 여부를 제어할 수 있습니다.

```python
import warnings

from hangulpy import HangulpyDeprecationWarning

# hangulpy의 제거 예정 API 경고만 숨깁니다.
warnings.filterwarnings("ignore", category=HangulpyDeprecationWarning)
```

테스트나 마이그레이션 점검 중에는 같은 필터의 동작을 `"error"`로 바꾸면 경고를
예외로 처리할 수 있습니다.
